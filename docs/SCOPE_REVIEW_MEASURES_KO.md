# 진행 수치와 완료 근거

기술 항목의 부분 검토, 상위 제목의 구조 분류, 계산 구현, API 교환, 입력 스키마와 수치 검증은 서로 다른 수치다. 상위 제목에 별도 본문이 추출되지 않았다고 해서 하위 요구나 다른 위치의 그림·부록이 완료되는 것은 아니다. 부분 검토 기록에 대조 구간이 없으면 그 사실을 별도로 남기고 구간 근거를 보강한다.

현재 범위 기록은 207개 부분 검토와 26개 추출 상위 제목의 구조 분류로 구분한다. 이 구분은 색인 탐색의 상태이며 전체 기술 요구를 끝까지 대조한 완료율이 아니다. 본문 구간의 기록은 겹침을 제거해 관리하지만 줄 수를 계산 과업의 비중으로 해석하지 않는다. 표·소개문·식·그림의 검토 비용과 구현 요구가 서로 다르기 때문이다.

계산 검토 수는 검토한 계산 부분집합의 크기다. 기존 코드의 요구 연결이나 검증 근거를 추가한 경우 신규 구현으로 표시하지 않는다. 사용자 규칙 조회와 계약 변환도 물리 계산 실적에 합치지 않는다. 등록 API 수와 Python/JSON 교환 확인 수를 구분하며 입력 스키마 연결률을 물리 모델의 완성도로 사용하지 않는다.

수치 검사는 명시한 입력·가정·해석해·보존식에 대한 확인이다. 자료의 권한과 독립성, 보정, 실제 재료 및 설비 적용성, 물리 검증은 별도로 기록한다. 전체 완료율의 분모가 확정되지 않은 동안에는 파일·API·항목·테스트 개수로 완료율을 만들지 않는다.

실제 계산 경로의 범위는 각 설명서를 따른다. 예를 들어 [과도 열전도와 두께 방향 열응력](THERMAL_GRADIENT_KO.md)은 기존 계산이며, 균일 구속식 하나만으로 제한되지 않는다. 반대로 이 경로가 존재한다고 전체 설비의 열충격·피로·파괴 적합성이 검증되는 것도 아니다.
