# 검사 모집단·표본 및 범위 확대 API

`inspection.lot_sampling_escalation`은 `matintegrity.models.inspection_sampling.InspectionLotSampling`을 받는다. 물리 부품별 모집단, 선택한 초기 표본, 반드시 초기에 검사할 부품, 검사 결과와 사용자 검사 계획을 명시한다. 한 요청은 하나의 검사 방법과 판정 기준만 다룬다. 서로 다른 방법·기준·모집단은 별도 요청으로 구분한다.

`InspectionSamplingPlan`에는 초기 표본 비율, 최소 초기 개수, 확대를 유발하는 고유 실패 부품 수, 확대 검사 비율, 초기의 확정 결과를 확대 검사 수에 재사용할지 여부를 넣는다. 필요한 수는 비율×모집단을 올림하고 초기 최소 개수도 적용한다. 비율은 JSON 숫자의 왕복 가능한 십진 표현으로 해석하므로 100개에 0.07이면 7개다. 확대 비율은 초기 비율보다 작을 수 없다. 최소 개수가 모집단을 초과하면 `out_of_scope`다.

`InspectionUnitOutcome`은 부품 ID, 초기 또는 확대 단계, `pass`·`fail`·`inconclusive`·`missing`, 기록 ID·해시·근거를 가진다. 미검사·판정불가는 이유가 필요하다. 모집단 밖 부품, 초기 표본 밖의 초기 결과, 중복 모집단 ID 또는 같은 부품·단계의 중복 결과를 거부한다. 재검사 이력을 임의로 덮어쓰는 입력으로 사용하지 않는다.

초기 선택한 모든 부품과 필수 초기 부품의 확정 결과가 필요하다. 실패도 검사 수행이 확인된 결과이므로 검사 완료 수에는 포함한다. 실패 개수가 사용자 조건에 도달하면 확대 검사 수를 확인한다. 최초 실패는 후속 단계에서 통과해도 실패 목록·확대 조건에서 사라지지 않는다. 초기 결과 재사용이 허용되면 그 확정 결과는 확대 검사 범위에도 포함된다. 재사용하지 않으면 별도 확대 단계의 확정 결과가 필요하다.

`required_inspection_coverage_complete`는 검토된 계획에 따른 검사 범위가 충족됐다는 뜻이다. 실패 부품이 있어도 검사 범위는 충족될 수 있으므로 제품 합격으로 사용하지 않는다. 실제 실패 ID는 별도로 보존한다. 미완료·미검토는 `needs_data`다. 확대 후 미확정 부품 목록은 후속 대상을 파악하는 목록이며 확대 비율이 1 미만이면 그 목록의 모든 부품이 필수라는 의미는 아니다.

결과는 모집단 크기, 초기·확대 요구 수와 확정 결과 수, 실패 목록·확대 조건, 초기 누락·필수 부품 누락, 계획 및 요청 해시를 제공한다. 기본 레지스트리의 Python/JSON API를 사용하며 실행 자산·위치가 요청과 같아야 한다.

표본을 무작위로 선정하거나 통계적 합격표를 생성하지 않는다. 신뢰수준·POD·고장확률·허용 판정·재검사 면제는 추론하지 않는다. 계획의 권한, 물리 모집단 완전성, 표본 선택, 결과의 검사 방법·기준 대응은 호출자가 검토한다. 내장 규격 표본 비율·실패 허용 수는 없다.

검증은 초기 범위 충족, 실패에 따른 확대, 확대 누락, 미검사·판정불가, 후속 통과 후 실패 보존, 초기 결과 재사용 정책, 십진 올림, 중복·모집단 외 결과 거부, 필수 부품 누락, 불가능한 최소 수 및 Python/JSON·문맥 일치로 구성한다.
