# 파일 기반 FMC 재구성

`inspection.file_homogeneous_fmc_tfm`은 동종 재료 직접 종파 경로를,
`inspection.file_planar_multiview_fmc_tfm`은 평면 경계 굴절과 평행 뒷면의
같은 모드 반사를 처리한다. 두 API는 기존 메모리 입력 재구성 커널을 공유한다.

## 입력과 저장 규약

파형은 행이 송수신 쌍, 열이 공통 시계 샘플인 숫자형 NPY 파일이다.
호출자는 전체 파일 SHA-256, 정확한 dtype·바이트 순서, 각 송수신 쌍의
저장 행 번호와 해당 행 원시 바이트의 SHA-256을 제공한다. 행 해시는
저장 dtype을 유지한 C 순서 바이트에서 계산한다. 이는 메모리 API의
정규화된 샘플 값 해시와 다른 계약이다. 객체 배열과 pickle은 허용하지 않는다.

최대 256개 요소의 모든 순서 있는 송수신 쌍이 정확히 한 번 필요하다.
누락 쌍을 만들거나 행 순서에서 송수신 역할을 추론하지 않는다. 시계·좌표·음속·
물리 시편·출처·원자료 해시와 계산 근거를 입력 계약에 명시한다.
정수 파형도 자동 물리 단위 환산이나 이득 보정 없이 저장 값을 사용한다.

## 실행과 자원 제한

숫자 배열을 읽기 전용 메모리 매핑으로 열고 영상 점들을 청크로 계산한다.
파일 크기, 전체 샘플 수, 전체 점-파형 평가 수, 청크당 기여 수와
캐시 행 수는 별도 입력 제한이다. 전체 영상과 메타데이터는 메모리에
보관하므로 프로세스 전체 메모리가 청크 제한만큼이라는 의미는 아니다.

호출자는 실행 중 파일 불변성을 확인해야 한다. 실행 전후 파일 해시와
파일 상태, 읽는 행의 해시를 확인하지만 운영체제 배타 잠금을 제공하지 않는다.
한 점·한 뷰라도 관측 시계나 경로 범위를 벗어나거나 파일이 변경되면
이전 청크의 부분 영상도 반환하지 않는다. 파일 부재는 `needs_data`,
지원하지 않는 저장 형식·예산·변경은 `out_of_scope`로 반환한다.

## 검증 경계

작성한 합성 파형으로 행 재배열, 청크 불변성, 바이트 순서와 정수 저장,
굴절·반사 뷰, 해시 불일치, 늦은 청크 실패, 파일 변경과 256개 요소의
전체 송수신 쌍을 확인한다. 작은 합성 배열의 256개 요소 실행은
다중 GB 파일 성능·최대 메모리·실제 장비 적합성 검증이 아니다.
진폭 전달계수·편광·일반 곡면·검출확률·결함 크기·검사 승인은 제공하지 않는다.
