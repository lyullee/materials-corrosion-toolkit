# 코팅 손상 범위와 세정조 재고

`fabrication.coating_damage_area_inventory`는 `matintegrity.models.fabrication_surface.CoatingDamageAreaInventory`를 받는다. 원래 코팅 면적과 실제 검사 면적(m²), 손상 패치별 ID·위치·면적(m²)·최대길이(m)·기록 해시와 근거를 입력한다. 패치 영역이 중복되지 않는다는 검토가 필요하다. 중복 영역을 자동 병합하거나 사진·좌표에서 면적을 추정하지 않는다.

출력은 알려진 손상 면적 합, 원래 면적 대비 알려진 손상 비율, 검사 면적 안의 손상 비율, 검사 면적 비율, 최대 패치 면적·길이와 각각의 패치 ID다. 면적 최대와 길이 최대는 다른 패치일 수 있다. 검사 면적이 0이면 검사 영역 내 손상 비율은 `null`이다. 알려진 손상 면적이 0이라는 값은 미검사 영역의 무손상을 뜻하지 않는다. 전체 검사 여부를 따로 보존한다. 손상 면적 합이 검사 면적보다 크면 `out_of_scope`다.

냉간 보수·열간 보수·재도금 선택은 별도의 권한 있는 사용자 기준으로 평가한다. 이 API는 그 판단에 쓸 관측 기하를 제공하며 면적 임계값·보수 재료·도금 복원 성능·수명을 내장하지 않는다. 실행 문맥과 요청의 자산·위치가 다르면 거부한다. 입력 스키마는 `docs/schemas/CoatingDamageAreaInventory.json`이다.

기존 `fabrication.chemical_cleaning_bath_component_inventory` 1.0.1은 빈 세정조의 농도 의미를 수정했다. 액체를 완전히 배출하여 액체 부피와 성분 질량이 모두 0이면 재고 상태는 계산 가능하지만 농도는 정의되지 않는다. 이벤트와 최종 농도 사전의 값은 이 경우 0 대신 `null`이다. 소비 코드는 농도 연산 전에 `None`인지 확인해야 한다. 양의 질량이 남아 있는데 액체 부피가 0이면 기존과 같이 `needs_data`다.

이벤트 처리 순서는 액체·성분 추가, 완전혼합 상태의 인출, 사용자 지정 성분 소비다. 추가 후 재고나 농도가 유한한 수치 범위를 넘으면 `out_of_scope`로 반환한다. 요청 자산·위치와 실행 문맥의 일치도 검사한다. 반응 속도·침전·밀도 변화·중화 효과·세정 완료를 추론하지 않는다. 입력 계약은 바뀌지 않았으며 출력의 빈 조 농도와 문맥 검사가 달라졌다.

검증은 부분 검사 손상 비율과 개별 극값 ID, 무검사 영역의 미정 비율, 과도한 손상 합·검토 누락, 혼합 인출 질량, 완전 배출의 미정 농도, 추가·인출·소비 순서, 인출 부족·수치 범위와 두 API의 Python/JSON·문맥 일치로 구성한다.
