# 사용자 분류번호 할당과 WPS 연결

`materials.declared_classification_assignment`는 사용자가 제공한 할당 기록을 정확히 조회한다. 분류번호·소그룹·용가재·용착금속 등 서로 다른 분류 목적은 `ClassificationContext`에서 별도 체계로 지정한다. 번호를 정수로 변환하지 않으므로 문자 접미사와 원래 토큰을 보존한다. 분류번호별 재료 표·할당 규칙·단종 이력은 내장하지 않는다.

조회마다 물리 품목 식별자와 `SpecificationDesignation`의 이름 공간·호칭·재료 판본·제품 형태·상태를 제공한다. 분류 문맥에는 규격 이름 공간·판본, 분류 체계, 공정, 대상 종류와 자격 목적이 모두 필요하다. 같은 품목이 같은 분류 문맥에서 서로 다른 재료 호칭을 갖도록 요청하면 거부한다. 호칭 별칭을 사용할 때에는 먼저 기존 정확 별칭 해석 API로 검토된 호칭을 얻고, 그 결과가 실제 제품의 동등성을 입증한다고 가정하지 않는다.

할당 기록에는 같은 호칭·문맥과 권한·개정·원자료 해시·할당 사유가 필요하다. 기록 전체를 별도 해시에 묶고, 사용 권한이 명시된 근거가 그 해시를 가리켜야 한다. 전체 요청은 `CorrelationBasis`에 연결한다. 조회는 해시 인덱스로 수행하며 다른 판본·제품·공정·상태로 유사 검색하거나 범주를 확장하지 않는다.

상태는 다음과 같다.

- `assigned`: 검토된 단일 기록에서 토큰이 명시됨
- `unassigned`: 검토된 단일 기록이 미할당을 명시함
- `unknown`: 일치 기록이 없거나 자료·권한 검토가 부족함
- `ambiguous`: 두 개 이상의 기록이 정확히 일치함

명시적 미할당은 자료 없음과 구분되며 숫자 0으로 바꾸지 않는다. 같은 토큰을 가진 두 기록도 권한·개정을 임의로 선택하지 않고 모호함을 유지한다. 출력에는 물리 품목·호칭·분류 문맥·후보 기록·할당 해시와 선택된 권한·개정·원자료 해시를 남긴다. `computed`인 미할당 결과가 용접 자격을 의미하지 않는다.

Python 연결 함수 `classification_to_wps_variable(request, query_id, variable_id=..., production_record_id=...)`는 검토된 단일 `assigned` 결과만 연결한다. 반환값은 `ClassificationWPSBinding`이며 조회·물리 품목·호칭·분류 문맥·선택한 할당 기록·요청 해시와 생산 변수를 하나의 연결 해시로 보존한다. 연결 해시를 유지한 채 품목이나 변수를 바꾸면 검증에서 거부한다. 이 해시는 연결 내용의 일관성 검사이며 외부 권한자의 전자서명은 아니다.

기존 WPS API에는 반환값의 `production_variable`을 전달한다. 이것은 `ProductionEssentialVariableRecord`이며 토큰을 범주형 값으로 유지하고 단위를 `1`로 지정한다. 원래 할당 기록과 요청의 근거도 보존한다. 다른 조회에 미상 결과가 있더라도 선택한 조회 자체가 단일 할당인지 확인한다. 선택한 조회의 미상·미할당·모호함·검토 누락은 변환 오류다. 감사와 재현을 위해 생산 변수만 보관하지 말고 전체 연결 결과도 함께 저장한다.

반환 변수를 WPS 평가에 전달할 때에도 양쪽 모재 상태·이음·공정·시험편·자격 범위와 근거를 기존 API에서 별도로 확인해야 한다. 이 연결은 분류 값을 전달하는 계약 변환이며, 용접성·재료 대체·충격시험 면제·자격 범위·규격 수락을 생성하지 않는다. 검증은 임의 작성 기록의 정확 일치·상태 구분·변조 거부·Python/JSON 교환·WPS 계약 연결과 기존 스키마 생성 회귀를 포함한다.
