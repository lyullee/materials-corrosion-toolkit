## 출력 파라미터

공통 반환 형식은 `AssessmentResult`다. 계산 값은 `values`, 단위는 `units`에 들어간다. 아래는 registry가 선언한 출력량이며, 조건부 분기의 모든 내부 키를 정형화한 출력 스키마는 아니다. `needs_data`·`out_of_scope`에서는 값이 비거나 진단만 반환될 수 있다.

| `values` 내 선언 경로 | 단위 |
|---|---|
| `history_id` | `1` |
| `event_count` | `1` |
| `event_history` | `1` |
| `final_liquid_volume_m3` | `m^3` |
| `final_component_mass_kg` | `kg` |
| `final_component_concentration_kg_m3` | `kg/m^3` |

공통 메타데이터: `model_id`, `model_version`, `status`, `inputs`, `values`, `units`, `assumptions`, `notes`, `context`, `input_digest`, `source_ids`, `qualification`, `runtime`, `probability_semantics`.

## 모델 가정·주의 사항

- Component masses are caller-declared and expressed on one consistent component identity basis.
- The vessel is spatially uniform and each liquid withdrawal removes components in proportion to the current mixed concentration.
- Operation order within an event is liquid/component additions, mixed liquid withdrawal, then caller-declared component consumption.

## 구현 근거·독립 설명

- `caller_declared_well_mixed_solution_component_inventory_balance`: Advance caller-declared component mass and liquid volume through ordered additions, perfectly mixed liquid withdrawals, and separately supplied component consumption. Preserve the caller's component identity, evidence and event order. This is inventory bookkeeping only; it does not infer chemical reactions, dissolution, cleaning performance, compatibility or acceptance.

## 실행 방법

```python
import json
from matintegrity.registry import default_registry
from matintegrity.contracts import RunContext

registry = default_registry()
model_id = "fabrication.chemical_cleaning_bath_component_inventory"
# inputs.json을 위 계약과 실제 평가 조건에 맞게 작성한다.
payload = open("inputs.json", encoding="utf-8").read()
context = RunContext(asset_id="your-asset", location_id="your-location", time_basis="elapsed seconds")
result = registry.run_json(model_id, payload, context)
print(result.status)
print(result.values)
```

위 코드는 호출 구조다. `inputs.json`, context, provider의 실제 준비가 필요하며 그대로 실행되는 재료 추천 예제가 아니다.

주 JSON 예제 파일에는 이 API의 독립 예제가 없다. 연결 API는 선행 계산의 실제 `AssessmentResult`가 필요할 수 있고 데이터 API는 별도로 확보한 파일·권한이 필요하다. 단위·계약·증거를 임의로 채워 실행 성공을 만들지 않는다.
