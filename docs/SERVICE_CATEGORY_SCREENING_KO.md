# 사용자 서비스 범주 선별

`workflow.service_category_screening`는 사용자가 작성한 범주 규칙에 관측 자료가 맞는지 비교한다. 규격의 실제 범주 정의·독성 기준·압력·온도 경계·제작 요건을 내장하지 않는다. 범주가 요구하는 재료·검사·제작 조건의 선정과 최종 분류는 책임 있는 사용자의 별도 업무다.

요청에는 설비·위치·물리 범위·설비 경계 식별자, 관측 사실, 분류 프로파일과 검토 상태를 넣는다. 프로파일마다 범주, 규격 이름 공간·판본, 같은 설비 경계, 판단 권한자, 개정, 필수 사실과 조건을 지정한다. 프로파일의 전체 규칙·권한·판본·필수 사실을 해시에 묶고, 사용 권한이 명시된 근거가 같은 해시를 가리켜야 한다. 전체 요청도 `CorrelationBasis`에 연결한다.

사실은 수치·서술·불리언 중 하나로 명시한다. 알려진 값에는 관측 기록·자료 그룹·해시·근거가 필요하다. 미상·무효 상태에는 값 대신 사유를 둔다. 수치와 불리언은 서로 변환하지 않으며 문자열을 불리언으로 해석하지 않는다. 수치 조건은 단위 토큰이 정확히 같을 때만 비교한다. 게이지·절대 압력, 온도 기준과 농도 기준은 입력 단계에서 구분해야 하며 여기서 변환하거나 추론하지 않는다.

한 규칙의 조건은 AND, 한 프로파일의 규칙들은 OR다. 필수 사실이나 조건에 미확정 사항이 하나라도 있으면 다른 거짓 조건으로 가리지 않고 `indeterminate`·`needs_data`를 유지한다. 권한·선정·범위·자료 검토가 완료되지 않은 경우도 같다. 모든 입력과 조건이 확인된 프로파일만 `matched` 또는 `not_matched`가 된다.

결과는 프로파일별 규격·판본·범주·개정·권한·해시·조건 근거와 맞은 프로파일 목록을 포함한다. 여러 범주가 맞아도 우선순위를 정하지 않고, 아무 범주도 맞지 않더라도 기본 범주를 배정하지 않는다. `classification_decision`은 항상 `not_made`다. 서로 다른 규격의 비슷한 이름을 동등한 범주로 합치지 않는다.

위험성 평가 연동 시 이 결과는 입력 조건과 판단 근거로 전달할 수 있다. 미확정을 거짓으로 바꾸거나 범주 일치 여부를 고장확률로 변환하지 않는다. 노출 위해성, 재료 열화 기구, 제작 범주와 사고 확률은 각각 필요한 근거를 유지한다. API 실행 시 설비·위치가 `RunContext`와 다르면 거부한다.

검사는 임의로 작성한 프로파일을 사용한다. 새 규칙·계약과 기존 손상기구 선별 회귀 27개는 소프트웨어 동작 확인이며 규격 적합성이나 물리 검증의 증거가 아니다.
