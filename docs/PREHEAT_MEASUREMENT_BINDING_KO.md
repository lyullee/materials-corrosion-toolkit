# 예열·패스 간 온도 이력 연결

버전 0.1.1은 선택적 패스 간 하한
`minimum_supported_interpass_temperature_K`를 독립적으로 비교한다.
이 하한을 선언하면 `minimum_recorded_interpass_temperature_K`와
`below_interpass_duration_s`가 필요하다. 없으면 `needs_data`다.
이력 연결 API는 같은 두 값을 실제 패스 간 구간에서 계산한다.
하한이 미제공이면 하한 여유와 이탈 시간은 `null`이며 예열값을 대입하지 않는다.
미제공 자체가 규격상 하한 면제라는 뜻은 아니다.

예열 요구와 패스 간 상·하한은 다른 단계의 조건이다. 예열 하한을 패스 간
상한보다 낮아야 하는 값으로 강제하지 않는다. 실제 절차의 가열·냉각·측정
시점과 각 패스 직전 조건을 확인해야 하며, 용접 아크가 켜진 구간을 패스 간
측정 구간으로 자동 해석하지 않는다. 새 선택 필드를 포함한 정규화 요청으로
입력과 근거 해시를 재생성한다.

루트 패스와 후속 패스의 요구값이 다르면 해당 구간과 절차 범위에 맞춰
평가 요청을 분리한다. 단일 템플릿을 적용한 여러 구간은 모두 같은 선언
경계를 사용하며, 구간 ID에서 패스별 다른 기준을 추론하지 않는다.

현재 `welding.preheat_procedure_envelope`는 사용자가 제공한 최저 예열온도,
최고 패스 간 온도와 경계 이탈 시간을 절차 범위와 비교한다.
`welding.heat_treatment_history`는 공통 시계의 온도 기록을 구간별 선형으로
보간해 동시 유지시간·가열/냉각 속도를 계산한다. 국부 열처리 API는 센서와
열영역의 기록을 별도로 대조한다. `welding.preheat_history_binding`은 측정
기록으로부터 예열·패스 간 집계값을 산출해 기존 절차 평가를 호출한다.

물리 범위·센서·내외면·좌표 및 위치 근거·시계·측정 해시를 보존하고 예열
구간과 패스 간 구간을 명시적으로 선택한다. 요구 측정 채널과 실제 기록은
정확히 일치해야 한다. 최솟값·최댓값과 경계 이탈 시간을 계산해 같은
자산·위치·용접부의 절차 평가로 전달하며, 레지스트리 실행 문맥도 대조한다.

`template`의 여섯 집계 입력은 `null`이어야 한다. 관측에서 산출한 값만 채운
기존 평가 요청과 그 해시를 반환하므로 임의 집계값으로 덮어쓸 수 없다.
구간은 순서대로 겹치지 않게 지정하고 두 단계가 모두 있어야 한다.
같은 시계에서 센서별 샘플 시점은 달라도 된다. 모든 채널이 각 구간을
지원해야 하며 `maximum_sample_gap_s`보다 큰 관측 간격은 보간하지 않는다.

구간별 선형 교차 계산은 유리수 중간 연산을 사용한다. 이탈 시간은 요구된
센서 중 하나라도 경계를 벗어난 시간의 합집합이므로 센서 수만큼 중복되지
않는다. 기존 열처리의 동시 유지시간과 다른 집계 정의다. 검사하는 샘플
구간마다 작업 예산을 적용하며 실패 시 부분 평가 요청을 반환하지 않는다.

누락 센서나 기록 밖 시간은 보간으로 채우지 않는다. 측정점의 온도로 미측정
관통 두께 전체의 균일성·수소 방출·균열 저항을 인정하지 않는다.
재료명·탄소당량·형상만으로 예열값·가열 폭·측정 거리를 자동 선정하거나
열처리 면제를 허용하지 않는다. 적용 판본·절차·자격과 측정 배치 근거는
호출자가 제공해야 한다.

적용 표에서 요구가 없다는 표기와 온도 0, 예열 금지, 조건부 면제는 서로
다르다. 논리곱·논리합 조건과 조성이 용탕 분석인지 제품 분석인지 또는
규정 경계값인지도 절차 근거에서 명시해야 한다. 이 연결 API는 이를 자동
해석하거나 불명확한 표기·단위를 교정하지 않는다.

검증 대상은 선형 교차 시점·구간별 이탈 시간의 해석해, 내외면/위치 혼합 거부,
시계·기록 범위 누락, 중복 측정 식별자와 Python/JSON 교환이다.
측정 이력의 산술·연결 검증은 센서 자격이나 실제 용접의 물리 적합성 검증과 다르다.
