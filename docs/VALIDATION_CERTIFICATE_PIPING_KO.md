# 성적서 식별자와 사용자 배관 클래스 확인

2026-11-01 로컬 합성 입력 검증 기록이다.

성적서 상위 문서 연결은 수정 전 서로 다른 제품의 coverage 기록을 넣어도 `pass`가 되는 경우를 재현했다. 1.1.0에서는 평가 대상 제품·추적번호와 검토 상태를 명시하게 하고, 불일치 문서 및 실행 컨텍스트를 거부한다. 이전 형식에서 대상 연결이 빠지면 `needs_data`를 반환한다. 상위 API 관련 6개와 하위 성적서 연결 관련 7개 테스트가 통과했다.

사용자 배관 클래스는 9개 테스트가 통과했다. 지원 곡선 중간점의 압력 여유, 재료·부식여유·속성 불일치, 누락 부품, 알려진 실패와 누락의 동시 보존, 서비스·온도 지원 범위, 다른 물리 범위의 부품과 중복 ID 거부, 실행 컨텍스트 및 Python/JSON 결과 일치를 확인했다. 압력 등급 문자열은 계산값으로 해석하지 않았다.

재현 파일은 `tests/test_certificate_campaign.py`, `tests/test_certificate_reconciliation.py`, `tests/test_certificate_reconciliation_v2.py`, `tests/test_piping_class.py`다. 프로젝트 루트의 Python 환경에서 `python -m pytest`로 지정해 실행할 수 있다. 실행 예제는 `examples/piping_class.py`다.

이 22개는 이번 검토에 새로 확인한 사례이며 재검토 범위의 누적 관련 테스트는 150개다. 숫자는 물리적으로 검증한 모델 수나 전체 저장소 테스트 수가 아니다. 실제 PMI 측정 범위, 제품 절단·마킹의 물리적 계보, 재료 동등성, 부식 내성 및 규격 승인에 대한 검증은 이 결과로 대체하지 않는다.
